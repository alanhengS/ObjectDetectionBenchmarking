Measured on 2026-11-12 (Apple M2 CPU; Apple M2 GPU (MPS)). Each configuration processed the same 100 COCO 2017 images per trial with YOLO11n, batch size 1. Times are elapsed workload processing time (preprocessing + inference + postprocessing).

## Observations (measured)

- **Shortest mean execution time:** CPU 320×320, 0.968 s for 100 images (9.68 ms/image).
- **Highest throughput:** CPU 320×320, 103.29 images/s.
- **Resolution effect on CPU:** CPU 640×640 → CPU 320×320 changed the mean time from 2.991 s to 0.968 s (-67.6%, speedup 3.09). The 320×320 input has one quarter of the pixels, so this is a change in workload, not in hardware.
- **Resolution effect on GPU:** GPU 640×640 → GPU 320×320 changed the mean time from 1.747 s to 1.140 s (-34.8%, speedup 1.53). The 320×320 input has one quarter of the pixels, so this is a change in workload, not in hardware.
- **CPU vs. GPU at 640x640:** Speedup 1.71 > 1: GPU-640 was faster than CPU-640 (1.71x the performance). (same workload, different processor)
- **CPU vs. GPU at 320x320:** Speedup 0.85 < 1: GPU-320 was SLOWER than CPU-320 (it took 1.18x as long). (same workload, different processor)
- **Consistency:** All configurations were consistent across trials (range as a percentage of the mean: CPU 640×640 2.5%, CPU 320×320 2.9%, GPU 640×640 5.1%, GPU 320×320 4.8%; threshold used: 10.0%).

## Unexpected results

- CPU vs. GPU at 320x320: the GPU was slower than the CPU (speedup 0.85).
- The faster processor was different at the two resolutions.

## Possible explanations (hypotheses — not measured)

These are possible reasons only. This project measured total elapsed time; it did not measure the individual parts below.

- With batch size 1 and a small model, each image carries fixed costs that do not shrink with a faster processor or a smaller input (CPU-side preprocessing and postprocessing, launching GPU work, and waiting for it to finish). If these are a large share of each image's time, the GPU's advantage and the benefit of a lower resolution would both be reduced.
- The CPU-to-GPU speedup was larger at 640×640. A larger input gives the GPU more work per image to run in parallel, which may make better use of it relative to the fixed per-image costs.
- Trial-to-trial variation may come from macOS background activity, power or temperature changes, or other apps sharing the unified memory.

## Experimental conditions

These results apply to this Mac, software versions, and conditions (power source, temperature, background apps). Other hardware, other model sizes, or other batch sizes may give different results.
